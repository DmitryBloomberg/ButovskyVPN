# Веб-магазин ButovskyVPN

Сайт использует ту же SQLite-базу, что и Telegram-бот: тарифы, статусы встроенных платежей, платежные заказы и VPN-ключи не копируются в отдельную систему.

## Что добавлено

- Регистрация и вход по электронной почте и паролю. Пароль хранится в виде PBKDF2-хэша; верификация почты по письму не включена.
- Список активных тарифов из базы бота.
- Способы оплаты из тех же настроек и провайдеров, что используются ботом. Веб-магазин не показывает Telegram-счета без привязанного Telegram-аккаунта.
- Счёт Stars отправляется сообщением в чат пользователя с ботом; успешную оплату обрабатывает существующий обработчик Telegram-платежей.
- Platega и другие настроенные ссылочные провайдеры создают платёж по общей системе Payment Intent. Сайт проверяет платёж и запускает штатную выдачу ключа.
- Личный кабинет показывает ключи и историю заказов.
- Переключение темы: тёмная, чёрная или светлая.
- Единственная дополнительная команда в боте — обработка одноразовой ссылки `/start web_…` для безопасной привязки аккаунта сайта. Главное меню и текущие сценарии бота не меняются.

## Запуск на Windows

1. Установите Python 3.11 или новее.
2. Запустите `start.bat`. Если `config.py` отсутствует, появится копия `config.py.example`.
3. Для Telegram Stars и работы бота укажите в `config.py` токен `BOT_TOKEN`, имя бота `BOT_USERNAME` и свой Telegram ID в `ADMIN_IDS`. Сохраните файл и перезапустите `start.bat`.
4. Откройте `http://127.0.0.1:8080`.

Без токена бот не запускается, но веб-сервер можно открыть для проверки интерфейса. Для реальной оплаты и выдачи ключей нужны заполненный `config.py`, настроенные серверы/тарифы и провайдеры в боте.

## Установка на Debian с доменом и HTTPS

До запуска направьте DNS-запись A/AAAA домена на VPS и откройте входящие порты 80 и 443. Затем в каталоге проекта выполните:

```bash
bash start.sh
```

До запуска направьте DNS-запись A домена на VPS, откройте входящие порты 80 и 443 и используйте чистую конфигурацию Nginx. Затем из каталога проекта выполните `bash start.sh` от обычного пользователя с настроенным `sudo` (так systemd-сервис работает без root). Сценарий запросит домен, скрытый ввод пути панели 3X-UI (или создаст случайный), токен Telegram-бота, Telegram ID администратора и имя бота.

Установщик подготовит системные и Python-зависимости, проверит SHA-256 закреплённого 3X-UI KIT v1.2.1, создаст стандартные подключения и QR-код, привяжет панель к боту через API-токен, настроит HTTPS сайта и systemd-автозапуск. Для домена 3X-UI KIT устанавливает Nginx stream и TLS-сертификат; доменный fallback Nginx проксирует сайт на `127.0.0.1:8080`, а панель доступна по IP/секретному пути. Токен API не публикуется и не выводится в файлы репозитория. Панель, Nginx и сервис сайта/бота включены в запуск после перезагрузки. При самоподписанном сертификате панели браузер покажет предупреждение.

Если уже установлены другая панель, активный сайт Nginx или заняты порты 80/443, сценарий остановится, не перезаписывая стороннюю конфигурацию. Для повторного запуска уже установленной панели KIT использует существующую конфигурацию.

Управление сервисом:

```bash
sudo systemctl status butovsky-vpn.service
sudo journalctl -u butovsky-vpn.service -f
sudo systemctl restart butovsky-vpn.service
sudo systemctl stop butovsky-vpn.service
```

## Привязка Telegram и оплата Stars

1. Пользователь регистрируется или входит на сайте по почте и паролю.
2. В личном кабинете нажимает **«Привязать Telegram для Stars»** и открывает полученную ссылку.
3. Пользователь нажимает **Start** в своём чате с ботом. Ссылка одноразовая и действует 15 минут.
4. После этого сайт показывает включённые Telegram-способы оплаты. При выборе Stars бот присылает счёт привязанному Telegram ID; существующий обработчик бота выдаёт ключ после успешной оплаты.

Для создания привязки сайт должен знать имя бота. Укажите `BOT_USERNAME` в `config.py`; при доступном Telegram Bot API имя также определяется автоматически.
Если стандартный Telegram Bot API недоступен с VPS, задайте рабочий адрес или список адресов `TELEGRAM_API_URL` в `config.py` — веб-счёт использует тот же сетевой клиент с переключением адресов, что и бот.

## Общая база и данные

База находится в `database/vpn_bot.db`. Бот и веб-сайт должны работать из одной копии проекта и использовать один этот файл. Не запускайте сайт и бот с разными копиями репозитория/SQLite-базы — тогда тарифы, платежи и ключи не будут общими. Перед переносом или обновлением сделайте резервную копию `database/vpn_bot.db`.

`config.py`, `.env`, журналы, виртуальное окружение и база исключены из архива как локальные/секретные данные. Настройте платёжные реквизиты штатно в админке бота; они останутся в общей базе.

## Переменные окружения

`run_all.py` читает простые строки `KEY=value` из локального `.env`, если он есть. Пример находится в `.env.example`. На Debian `start.sh` задаёт конфигурацию и сам создаёт `config.py`; токен не добавляйте в публикуемые файлы.

Для HTTPS задайте `WEB_BASE_URL=https://ваш-домен` и `WEB_COOKIE_SECURE=true`. Сайт слушает `127.0.0.1:8080` за Nginx; сертификат и внешний доступ обслуживает Nginx/Certbot.
